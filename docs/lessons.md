# Уроки: найденные баги

Пять ошибок, которые я поймал при разработке, — каждая учит чему-то общему.

## 1. «destroy is not a function»

```ts
useEffect(() => webApp?.MainButton.hide(), [])   // ✗
```

Стрелка без фигурных скобок **возвращает** результат выражения. React
считает возвращённое значение функцией уборки и при размонтировании пытается
его вызвать. `undefined` React пропустит, а методы `MainButton` возвращают
сам объект кнопки (для цепочек `setText(…).show()`) — и React падает, пытаясь
вызвать объект как функцию. В браузере, где `webApp` равен `null`, ошибки нет —
она проявляется только внутри Telegram.

```ts
useEffect(() => {
  webApp?.MainButton.hide()
}, [])                                            // ✓
```

**Вывод:** в `useEffect` — всегда тело в фигурных скобках, а уборку
возвращать явно. Линтер с правилом для этого не всегда спасает.

## 2. Сброс черновика раньше перехода

Было: после сохранения — `draft.reset()`, затем переход на «Готово». Но
`reset` перерисовывает экран подтверждения **с пустым черновиком**, а он
устроен так: «нет черновика → `<Navigate to="/" />`». Этот `Navigate`
срабатывал раньше перехода к успеху, и пользователь оказывался на главной.

Исправление: черновик очищает экран успеха при монтировании.

**Вывод:** изменение стора перерисовывает **все** подписанные компоненты,
включая тот, с которого вы уходите. Порядок «сначала уйти, потом убрать» —
надёжнее.

## 3. «Назад» после записи

`/ → /book → /confirm → /done` — «назад» возвращал в форму уже сделанной
записи. Решение — `restartAt()`: новый MemoryRouter с историей `['/', '/done/id']`
через смену `key` (глава 04).

**Вывод:** думайте об истории переходов как о части интерфейса. После
необратимого действия (оплата, отправка) назад в форму пускать нельзя.

## 4. `Date.now()` в рендере

Линтер React Compiler (`react-hooks/purity`) ругался: рендер должен быть
чистой функцией, а `Date.now()` каждый раз разный. Время создания записи
перенесено в стор (`add` сам проставляет `createdAt`), а «сейчас» для
расписания передаётся параметром в функции `lib/`.

**Вывод:** нечистое (время, случайность, хранилище) — по краям: в
обработчиках, сторах, эффектах. Чистое ядро проще тестировать.

## 5. Тест нашёл два элемента вместо одного

Playwright в строгом режиме падает, если локатор нашёл больше одного
элемента. `getByText('Маникюр')` находил и категорию, и услугу. Помогли
точные селекторы (`.service`) и `getByRole` с `name`.

**Вывод:** это не «тест капризничает», а подсказка: на странице правда два
похожих элемента, и пользователю скринридера их тоже трудно различить.
