# 04. Расписание и записи

Бизнес-логика «Мяты» — в `src/lib/`: обычный TypeScript без React, его легко
читать и тестировать (`npm test`).

## Время как числа

Время дня хранится **минутами от полуночи**: 10:00 → 600, 21:00 → 1260. Даты —
строками `YYYY-MM-DD`. Так нет часовых поясов, `Date` с его сюрпризами
появляется только в форматтерах (`lib/dates.ts`), а сравнение и арифметика
тривиальны:

```ts
export type Interval = { from: number; to: number }        // [from, to)
export const overlaps = (a: Interval, b: Interval) => a.from < b.to && b.from < a.to
```

Формула пересечения полуинтервалов — классика, её спрашивают на
собеседованиях. Запомнить: «каждый начинается раньше, чем кончается другой».
Полуинтервал `[from, to)` значит: запись 10:00–11:00 и запись 11:00–12:00
**не** пересекаются.

## Свободные окна

`freeStarts(master, date, duration, now, taken)` перебирает старты с шагом
`STEP = 30` минут и оставляет те, где:

- мастер работает в этот день недели;
- услуга целиком помещается до закрытия (`t + duration <= STUDIO.close`);
- если дата сегодняшняя — до начала не меньше часа (`LEAD_MINUTES`);
- отрезок `[t, t + duration)` не пересекается ни с одной занятой записью.

Занятость складывается из двух частей: записи «других клиентов» и **свои**
записи пользователя к этому мастеру (`takenIntervals`). Без второй части можно
было бы записаться к одному мастеру дважды на одно время.

## Детерминированная «занятость»

Бэкенда нет, но пустое расписание выглядит фальшиво. Нужна псевдослучайная
занятость, **одинаковая при каждом открытии**: иначе выбранное окно могло бы
«занятым» стать после перезагрузки.

```ts
const rnd = seeded(hash(`${masterId}:${date}`))
```

- `hash` (FNV-1a) превращает строку в число;
- `seeded` (mulberry32) — генератор: одинаковое зерно → одинаковая
  последовательность «случайных» чисел.

`Math.random()` так не умеет — у него нет зерна. Этот приём пригодится для
тестовых данных, генерации карт в играх, стабильных аватарок.

## «Любой мастер»

Если пользователь выбрал «Любой», `daySlots` берёт всех мастеров нужной
категории, сортирует по рейтингу и для каждого времени ищет **первого
свободного**. Слот хранит, кто именно его закроет (`masterId`), — на экране
подтверждения уже конкретное имя (`draft.resolvedMasterId`).

## Черновик записи

Запись собирается на нескольких экранах: услуга → мастер, дата, время →
комментарий. Промежуточное состояние — в сторе `store/draft.ts`, а не в
адресе: адрес у MemoryRouter не виден пользователю, а прокидывать данные через
`navigate(path, { state })` неудобно и теряется при перезапуске экрана.

Если пользователь попал на «Подтверждение» без черновика (например, нажал
«назад» после успешной записи), экран делает `<Navigate to="/" replace />`.

## Сохранение: сначала записать, потом показать

```ts
add: async (draft) => {
  const booking = { ...draft, id: crypto.randomUUID().slice(0, 8), createdAt: Date.now() }
  const list = [...get().list, booking]
  await persist(list)    // если упадёт — исключение, состояние не тронуто
  set({ list })
  return booking.id
}
```

Обратный порядок («оптимистичное обновление») быстрее на вид, но тогда при
ошибке хранилища запись мелькнула бы и пропала. Для записи к мастеру важнее
честность: пользователь видит «Вы записаны!», только если это правда.

## Роутер: MemoryRouter и «перезапуск истории»

Почему не BrowserRouter: GitHub Pages не умеет отдавать `index.html` на любой
путь, а Telegram открывает строго тот адрес, что указан в боте. Почему не
HashRouter: hash занят параметрами Telegram (`#tgWebAppData=…`).
**MemoryRouter** хранит историю в памяти — адрес не меняется вообще.

Отдельная задача — история после записи. Путь был
`/ → /book/x → /confirm → /done/123`. «Назад» с экрана успеха вернул бы в форму
подтверждения уже сделанной записи. Нужно: `/ → /done/123`.

У MemoryRouter нельзя переписать прошлые записи истории. Зато можно создать
**новый** роутер со своей начальной историей — через смену `key`:

```ts
// store/nav.ts
export const restartAt = (path: string) =>
  useNav.setState((s) => ({ key: s.key + 1, entries: path === '/' ? ['/'] : ['/', path] }))

// App.tsx
<MemoryRouter key={key} initialEntries={entries} initialIndex={entries.length - 1}>
```

Смена `key` — штатный способ React сказать «это другой компонент, создай
заново». Пригодится и в других местах: сбросить форму, перезапустить анимацию.

## Тесты

`schedule.test.ts` и `bookings.test.ts` проверяют пересечения, «не раньше чем
за час», выходные мастеров, «любого мастера», разбор битых данных и лимит
хранилища. Время в тестах **передаётся параметром** (`now: Date`), а не
берётся внутри функций, — поэтому тесты не зависят от того, когда их
запустили.

## Ошибки

> **Время строками «10:30».** Сравнивать и складывать неудобно. Минуты от полуночи — числа.
>
> **Пересечение интервалов «на глаз».** Отрезки `[from, to)` пересекаются, если
> `a.from < b.to && b.from < a.to` — одна строка вместо пяти условий.
>
> **`Math.random()` для занятости.** При каждом открытии другие окна — выбрали 14:00, вернулись, а
> оно «занято». Генератор с зерном из мастера и даты.
>
> **Показать запись до сохранения.** Хранилище отказало, а человек видит «Готово». Сначала
> записать, потом показать.
>
> **«Назад» с экрана успеха возвращает в форму.** История с нуля после записи (`restartAt`).

## Попробуйте сами

1. Мастер занят с 11:00 до 12:30. Свободно ли окно 12:30–13:30 для услуги на час?
2. Сейчас 14:20. Какое самое раннее время записи на сегодня?
3. Почему «Любой мастер» показывает время, а запись создаётся с конкретным мастером?

<details>
<summary>Ответы</summary>

1. Да: `[11:00, 12:30)` и `[12:30, 13:30)` не пересекаются — `12:30 < 12:30` ложно.
2. Не раньше 15:20 (`LEAD_MINUTES = 60`), по сетке шагом 30 минут — 15:30.
3. Время свободно, если свободен хоть кто-то из подходящих; при выборе берётся самый высокий по
   рейтингу из свободных (`masterId` в слоте), он и записывается.
</details>
